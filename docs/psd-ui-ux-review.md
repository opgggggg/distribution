# PSD 编辑器 UI/UX 走查

日期：2026-09-20。使用 ui-ux-pro-max 的可访问性、布局、反馈及键盘交互检查项；以当前编辑器的桌面工作流为准。初轮走查后，已完成下列六项修复及交互复测。

## 范围与结论

实际操作当前 Vue 源码预览：1280×720 主窗口、1024×600 嵌入窗口、375×667 嵌入窗口；合成 PSD 含文本、组、普通图层及蒙版。嵌入窗口通过同源 iframe 给编辑器真实的布局尺寸，并非缩小截图。检查了主题属性、图层选择、滤镜预览取消、键盘焦点、新建校验、未保存关闭、撤销和缩放。

初轮发现 2 个 P1、4 个 P2，现已全部修复。以下问题段落保留修复前的复现证据和代码位置。

## P1：默认高度分配让图层列表消失

- **复现**：1280×720，Color、Properties、Layers 三组均展开，打开测试 PSD。
- **实测**：右侧总高度 462.5 px，网格分配 `184px 5px 216px 5px 52.5px`。Layers 内容区仅 20.5 px，树列表顶部在 y=739.5，已经低于窗口底部 720。屏幕只能看到 Layers 标题和部分混合模式控件。
- **影响**：进入编辑器后最常用的图层选择/蒙版入口不可见，需要先自行发现折叠或拖分隔条；更低窗口会进一步恶化。
- **位置**：`packages/psd/src/vue/PsdRightPanels.vue:50`，默认高度在第 23–24 行。最后一行 `minmax(0, 1fr)` 可以降至零，`LOWER_MIN_HEIGHT` 只用于手动调节边界，初始布局与窗口 resize 没有保底分配。
- **修复方向**：根据实际可用高度重分配上两组，为 Layers 留出最低有效高度；空间不足时自动折叠次要面板，并保留清晰的恢复入口。
- **验收**：1280×720 和 1024×600 初次进入，无需操作面板布局即可看到至少两行图层及基本操作；窗口缩放后仍满足。

## P1：主题契约未接通，暗色标签对比度只有 1.16:1

- **复现**：默认 Move 参数浮层中查看 Auto-select / Show transform controls，或 Color 面板的 Foreground / Background 标签。另用 `appearance="light"` 加载同一编辑器。
- **实测**：Auto-select 标签为 `rgb(50,49,48)`，背景 `rgb(59,59,59)`，对比度约 **1.159:1**。浅色参数也没有切换侧栏与工具面板。
- **原因证据**：实际 shell DOM 只有透传的 `appearance="light"`、`default-appearance="dark"`，没有 CSS 所依赖的 `data-appearance`；当前安装的共享 shell 类型没有相应 appearance 属性。结果同时出现浅色 ribbon、深色面板与深色控件标签。
- **位置**：`packages/psd/src/vue/PsdEditor.vue:542`；`packages/psd/src/vue/styles.css:25`、`:33`、`:284`。
- **修复方向**：适配当前共享 shell 的主题契约，或在 PSD 自己控制的 DOM 上输出主题属性并覆盖完整的语义 token；检查共享控件是否在自身重设 token。
- **验收**：浅/暗参数都实际生效，普通标签至少 4.5:1；输入、下拉、焦点及浮层颜色一致。不能仅看 shell 外观判断主题通过。

## P2：未保存关闭提示没有焦点管理或 Escape 路径

- **复现**：复制一个图层产生未保存更改，再点击项目标签的关闭按钮。
- **实测**：出现 `role="dialog"` 的内联提示，但焦点仍留在原关闭按钮；按 Tab 到达提示外的 New project；按 Escape 提示仍存在。背后编辑器也保持可操作。提示插入布局并把画布整体向下推。
- **影响**：键盘/读屏用户无法直接理解或完成关闭决策，容易继续操作错误区域。此项属于独立 `PsdWorkspace` 项目栏，未据此推断 CubeOffice 宿主自己的标签关闭逻辑。
- **位置**：`packages/psd/src/vue/PsdWorkspace.vue:207`。
- **修复方向**：使用现有 UiDialog/确认组件，打开时聚焦 Keep editing、限制焦点范围、Escape 取消，关闭后返回来源；增加“保存并关闭”可作为后续便利项。
- **验收**：仅用键盘完成继续编辑/放弃更改，背景不接收快捷键，提示不改变画布布局。

## P2：缩放显示值与滑块实际值不一致

- **复现**：文档显示 100%，聚焦状态栏 Zoom 滑块并按一次右方向键。
- **实测**：初始 range 的 `value=88,min=13,max=800,step=25`，可见输出却是 100%。按右键后输出变成 **113%**。没有 `aria-valuetext` 修正读屏提示。
- **原因**：100 不是从 min=13 开始按 25 步进的有效点，浏览器将 range 值约束到 88。
- **位置**：`packages/psd/src/vue/PsdEditor.vue:601`。
- **修复方向**：滑块使用能够表达所有目标值的步长，按钮的 25% 步进单独处理；或采用明确的倍率档位映射，统一显示、键盘和读屏数值。
- **验收**：100% 时视觉值、DOM 值、读屏值一致；键盘每步遵守界面约定，不出现意外的 113%、138%。

## P2：窄屏侧栏盖住画布，没有自动收起入口

- **复现**：同一工作区放入 375×667 的真实布局容器。
- **实测**：画布区域 x=0…375，右 dock 占 x=55…375、宽 320 px，左工具栏约 44 px。侧栏覆盖了绝大多数画布。Ribbon 已有 More 菜单与横向滚动，但 dock 没有同步退化成按需展开的面板。
- **位置**：`packages/psd/src/vue/PsdEditor.vue:594` 的常驻 right-dock 接入；需与共享 dock 的窄屏布局一起处理。
- **修复方向**：窄屏默认关闭检查器，通过明确按钮呼出抽屉；同时只允许一个浮层占用画布。若明确不支持窄屏，至少提供最低宽度提示，不呈现看似可用但被遮满的编辑区。
- **验收**：关闭检查器后能直接操作画布，并能重新打开图层/蒙版面板；工具与检查器不会同时遮挡整个画布。

## P2：新建表单将底层异常直接显示给用户

- **复现**：New project，Width 输入 0，点击 Create project。
- **实测**：显示 `RangeError: width must be an integer between 1 and 30000.`；焦点仍在 Create project，没有 Width 就地错误、`aria-invalid` 或自动聚焦。
- **位置**：`packages/psd/src/vue/PsdWorkspace.vue:66`、`:267`。
- **修复方向**：提交前校验并将错误关联到字段，提示“宽度须为 1–30000 的整数”；聚焦第一个错误字段，保留输入。
- **验收**：空值、0、负数、小数、超上限均有可理解且可读屏的错误反馈，不出现异常类名。

- 图层树可通过 Enter 选择；选中后 ribbon 从文本切换到适用功能。

- 窄屏 ribbon 的 More 入口、横向滚动控制存在，没有将其与 dock 遮挡问题混为一谈。
