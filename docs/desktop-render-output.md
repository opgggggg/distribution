# CubeOffice desktop rendering and output

The macOS **File** menu and the other desktop hosts’ in-window application menu use the active document’s snapshot. **Export PDF** keeps the available pages, while **First page (PNG)** writes one image (the whole canvas for a PSD or a raster image). Printing uses the same PDF preparation as the file menu, except that protected OFD files go through their own print dialog and policy. The desktop host still suppresses the standard print menu on Windows.

The Office vector PDF exporter depends on the existing document layout and JavaScript PDF writer. The Rust PDF kernel rasterizes its output when an image is requested. Notebook pages continue to use their existing painter. A renderer error is surfaced to the user so it cannot turn into a blank or mislabeled download.

The Illustrator workspace imports simple path paint programs as individually editable objects. If an artboard cannot be reconstructed as a whole (for example, it has live source text, embedded images, clipping, or unsupported effects), it is rendered once as a locked background. New objects can be drawn over that background. Original Illustrator files save to a new .ai path. The new file contains a PDF view plus the CubeOffice editing model, so it can be reopened in CubeOffice. Adobe-private layers and effects remain in the original file.

In the Illustrator workspace, Shift-click adds or removes objects and dragging from empty canvas space selects the objects inside the rectangle. Grouped objects stay together during alignment and distribution. Use Direct Selection or Option/Alt-click to edit a group member on its own. The editable copy stores group membership along with the artwork.
