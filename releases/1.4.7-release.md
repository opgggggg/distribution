2026-09-19 发布。四平台（macOS arm64 / Windows x64 / Linux x86_64 / Android）已上线
cubexp.com；鸿蒙候选包已构建签名，待提交华为审核。

源码身份：distribution `e1658d4dbc2ec977948090f83f4788808775461e`，
upstream `c52cfe1a61f61ba5bd3bca695e149332cca2472d`。五个平台消费同一个提交。

## 这一版修了什么

1.4.6 的 `fix(mobile): keep offline template and feedback UI quiet` 用
`navigator.onLine` 决定是否隐藏演示模板和意见反馈入口。**ArkWeb 在应用没有
`ohos.permission.GET_NETWORK_INFO` 时，这个值联网断网都返回 false**，而本应用只声明了
`INTERNET`——于是鸿蒙上这两个功能对所有人恒定消失，与有没有网无关。Android 同样缺
`ACCESS_NETWORK_STATE`，WebView 那边也报不出网络状态。

修法不止是补权限（`a22be18`）：网络状态改由原生宿主回答，
`HarmonyDocumentBridge.hasNetwork()` 用 `connection.hasDefaultNetSync()`，
`MainActivity.hasNetwork()` 用 `ConnectivityManager.getActiveNetwork()`，Web 侧
`isOffline()` 优先问宿主、浏览器壳才回落到 `navigator.onLine`，**读不到一律算在线**——
判错不能把功能拿走。模板画廊不再提前跳过请求，反馈面板回到前台时重读状态。
审核关心的离线表现没变：离线仍然没有红条、没有反馈入口。

1.4.6 的离线红条正是 1.4.5 被驳回的原因（见 [1.4.5-huawei.md](1.4.5-huawei.md)），
那一版修复已于 2026-09-17 过审，AGC 现在在架的是 1.4.5。

## 新增的鸿蒙发布脚本

`scripts/release-harmony.sh`（`345ab6c`）把原先靠复盘文档口口相传的构建签名步骤固化：
写 `releases/harmony-v<version>.md` 即发起，`check → build → sign → report`，停在签名
候选包并打印 AGC 待办。版本号取自 `profiles/cubeoffice/app.json`，脚本不改它；源码树不
干净、签名材料缺失、候选包已存在都直接停——审核中的包绝不能被悄悄重建。
发布时用 `--source ~/cubexp.com/releases/<version>/automation/source` 与其余平台同源。

AGC 的「新版本特性」和网站发布说明是两回事，所以鸿蒙说明单独成文件：鸿蒙用户从未拿到
1.4.6，对他们而言 1.4.7 的看点是 Markdown 流程图和 EMF 展示改进，而不是那个他们没遇到
过的 bug（`d5006bb`）。

## 过程中踩到的坑

- **DevEco 自带 Node 18**：`release-harmony.sh` 最初把它加进全局 PATH，仓库要 20+，
  web 构建直接挂。现已只在 ohpm/hvigor 两条命令上生效。
- **裸 `npm run build:web` 会改应用身份**：不带 `APP_PROFILE=cubeoffice` 时 profile
  sync 把包名、版本号、应用名和图标写回默认的 AuroraPrime Office，曾被 `git add -A`
  误提交后剔除。发布外的构建务必带 profile。
- **Windows 构建机磁盘**：发布要求 4 GB 空闲，实际只剩 1.81 GB。旧的
  `cubeoffice-auto-1.4.5/1.4.6` 构建树是唯一可回收的（缓存类合计只有 0.65 GB），
  删除后恢复到 9.65 GB。脚本只清理同版本的失败残留，跨版本需要人工决定。
- **AGC 表单在 iframe 里且页面不滚动**：「版本选取」和弹窗底部按钮压在可视区外，
  只能用 JS `scrollIntoView` 后再点。
- **发布脚本 `all` 不中途询问**：我曾说会在 publish 前停下来确认，但已启动的 `all`
  会一路发布完，实际没有停。要分段确认就得显式跑 `prepare` / `build` / `stage` /
  `publish`。
